01

What is Artificial Intelligence?

Foundations

Intelligence is the ability to acquire knowledge and apply it to solve problems. Artificial Intelligence (AI) is the field concerned with building machines that perform tasks normally requiring human intelligence. The goal is to match or exceed human capability on specific, well-defined tasks — not necessarily to replicate general human thought.

AI is a broad umbrella that has evolved through several approaches, all of which still count as AI:

  • Rule-based systems — explicit human-written logic ("if this, then that").
  • Statistical learning — methods that infer patterns from data.
  • Modern neural networks — multi-layer models behind today's most capable systems.

In short, AI is any technique that makes a machine act "smart" — including search, planning, and rules, not only learning from data.

AI vs Machine Learning vs Deep Learning

Foundations

These three terms are often used loosely, but they are precisely nested fields — each one is a subset of the one before it:

AI  ⊃  Machine Learning  ⊃  Deep Learning

FieldWhat it is
Artificial IntelligenceThe outermost set — any technique that makes machines act "smart": rules, search, planning, and machine learning.
Machine LearningA subset of AI that learns patterns from data instead of being hand-coded.
Deep LearningThe innermost subset — uses multi-layer neural networks and powers large language models (LLMs).
★
Remember: the innermost subset is Deep Learning. The nesting order AI ⊃ ML ⊃ Deep Learning is a recurring exam point.
03

Classical Programming vs Machine Learning

Foundations

The defining difference between the two is who writes the rules.

Classical Programming

The human writes the rules

  • Inputs: rules (written by a human) + data
  • Output: answers
  • Great when the rules are known and stable
  • Hard for messy tasks like vision and language
Machine Learning

The machine learns the rules

  • Inputs: data + example answers
  • Output: the rules (a trained model)
  • Learns the input→output mapping from examples
  • Excels where rules are hard to write by hand

So the flow is reversed: classical programming takes rules + data → answers, while machine learning takes data + answers → the rules (the trained model). Choose classical programming when the rules are known and stable; reach for ML when the rules are hard to write by hand.

04

Models and Algorithms

Foundations

"Model" and "algorithm" are easy to mix up, but they refer to two different things:

TermMeaning
AlgorithmThe procedure — the "recipe" that learns patterns from data. Example: gradient descent.
ModelThe trained artifact the algorithm produces: the learned parameters / weights that map inputs to outputs.

Think of it as recipe versus finished dish: the algorithm is the learning procedure; the model is what you get out the other end once learning is done. A key practical consequence: you train once — which is compute-heavy — and then run inference many times, which is much cheaper, on new data.

★
Don't reverse these: the algorithm learns; the model is the learned weights. Exam distractors frequently swap the two definitions.

The Universal ML Learning Loop

Optimization

Almost every machine learning method — from linear regression to deep neural networks — is the same feedback loop. At its core, learning means repeatedly nudging the parameters in the direction that lowers the error.

Step 1
Predict
guess from the current weights
Step 2
Measure
loss = how wrong the guess is
Step 3
Adjust
update the weights
Step 4
Converge
repeat until loss stops improving

The loop runs predict → measure loss → adjust the weights → repeat, continuing until the model converges. Convergence is the point at which the loss stops improving — the signal that the learning loop can stop.

07

Linear Regression & the Loss Function

Optimization

Linear regression is the simplest ML model: it fits a straight line to the data.

y = w·x + b

Training finds the slope (w) and the intercept (b) that best fit the data. Predicting a continuous target from labeled data this way is an example of supervised regression.

The loss function

A loss function measures "how wrong" the predictions are — it quantifies the prediction error. The goal of training is to minimize the loss. Two common choices:

LossHow it treats errorsEffect
MSE — mean squared errorSquares the errorsPenalizes large errors heavily — large mistakes dominate.
MAE — mean absolute errorScales errors linearlyRobust to outliers.
!
If a problem wants large errors punished hard, choose MSE. If the data has outliers you don't want to dominate, choose MAE.
08

Gradient Descent — the Core Optimizer

Optimization

Gradient descent is the most important optimization algorithm in AI — the engine that actually minimizes the loss.

  • The gradient is the direction of steepest increase of the loss. Because it points "uphill", descent steps in the opposite direction to reduce loss.
  • The size of each step is the learning rate. A too-large learning rate overshoots — loss may oscillate or diverge; a too-small learning rate converges very slowly.

The three variants

VariantData per stepTrade-off
Batch GDAll the dataStable but slow.
Stochastic GD (SGD)One sampleNoisy but fast.
Mini-batch GDSmall batchesBalances stability and speed — the practical default.

Adaptive optimizers

Momentum and Adam improve on plain gradient descent by adapting the step to accelerate and stabilize training. Mini-batch GD with Adam is the common modern default.

★
Remember: gradient descent steps opposite the gradient by a learning-rate-sized step. Mini-batch is the default variant; Adam/Momentum are the adaptive upgrades.
09

Three Types of Machine Learning

Paradigms

The three paradigms are distinguished by what the data looks like and what feedback the model receives.

Supervised

Learns from labels

  • Labeled data: input → known output
  • Tasks: classification & regression
  • Learns to reproduce the labels
  • Most enterprise ML today
Unsupervised

Finds structure

  • No labels — discover hidden structure
  • Tasks: clustering, dimensionality reduction
  • Discovers groupings / patterns
  • e.g. customer segmentation
Reinforcement

Learns from rewards

  • An agent acts in an environment
  • Learns from rewards & penalties
  • Trial-and-error over time
  • e.g. game-playing, RLHF for LLMs
★
One-line test: labels → supervised; no labels, find structure → unsupervised; rewards & penalties → reinforcement.
10

Classification Algorithms

Classical ML

Classification is the supervised task of putting examples into categories. Know these five algorithms and their one defining trait:

AlgorithmKey idea & trait
Logistic RegressionPasses a linear combination through the sigmoid to output a probability, giving a linear decision boundary. Despite the name "regression", it classifies.
Decision TreesA series of if/else splits; highly interpretable, but can overfit.
Support Vector Machine (SVM)Finds the maximum-margin boundary between classes.
K-Nearest Neighbors (KNN)Classifies by majority vote of the closest examples.
Naive BayesProbabilistic; assumes feature independence; a strong baseline for text.
!
The classic trap: logistic regression is a classifier, not a regressor, even though "regression" is in its name.

Unsupervised Learning — Finding Structure

Classical ML

Unsupervised methods work on unlabeled data, looking for structure rather than reproducing known answers. The two headline methods:

MethodWhat it does
K-Means ClusteringPartitions data into k groups around centroids — and you choose k.
PCAPrincipal Component Analysis — reduces dimensionality while keeping the most variance possible.

Common uses

  • Segmentation — group similar customers or items together.
  • Anomaly detection — flag what doesn't fit any cluster.
  • Compression & visualization — make high-dimensional data manageable and viewable (a natural fit for PCA).
12

Feature Engineering

Data

Feature engineering is the work of turning raw data into informative inputs the model can learn from. The deck stresses it is often the highest-leverage step in a project — good features beat a fancier model running on weak features.

Common techniques

  • Scaling / normalization — put features on a comparable range so none dominates by sheer magnitude.
  • Encoding categoricals — convert categories into numbers via one-hot, ordinal, or embeddings.
  • Creating new features — ratios, interactions, and date-derived values — then selecting the useful ones.
13

Overfitting vs Underfitting (Bias–Variance)

Generalization

This is the central tension in fitting any model. A good model balances the two failure modes below.

Overfitting — High Variance

Memorizes noise

  • Low training error, high test error
  • Memorizes noise; fails to generalize
  • Fixes: more data, simpler model
  • Regularization (L1/L2, dropout), early stopping
Underfitting — High Bias

Too simple

  • High error on both train and test
  • Model too simple to capture the pattern
  • Fixes: add features / complexity
  • Train longer, reduce regularization

Reading the signatures

SymptomDiagnosis
Low train error, high test errorOverfitting (high variance)
High error on both train and testUnderfitting (high bias)

A few cause-and-effect notes worth memorizing: adding parameters/capacity worsens overfitting; over-regularizing causes underfitting (reduce it to restore capacity); dropout randomly disables units during training as a regularizer; and early stopping halts training as validation performance turns.

★
Remember: Overfitting = high variance. Underfitting = high bias.
14

Train / Validation / Test Split

Evaluation

To estimate real-world performance honestly, data is split into three sets, each with a distinct job:

SetPurpose
TrainingFit the model's parameters (the weights).
ValidationTune hyperparameters and choose between models.
TestA final, unbiased estimate — used only once, at the very end.
  • A typical split is around 70 / 15 / 15.
  • Never let test data leak into training or tuning. Using the test set to tune leaks it into development and inflates the estimate upward — the test set must stay isolated.
  • Cross-validation (covered on Day 5) reuses data when it is scarce.
★
Remember: training fits, validation tunes/selects, test gives a single honest final estimate. Test-set leakage is the cardinal sin of evaluation.

How a Network Learns (Part B)

Neural Nets

Forward and back propagation together form the neural-network training loop. Inputs flow forward to a prediction; the error flows backward as gradients; gradient descent then updates the weights.

1
Forward pass
predict
2
Loss
measure error
3
Backprop
gradients per weight
4
Update
gradient descent

Gradients & vanishing gradients

A gradient tells how much and in which direction to change each weight. In very deep networks, gradients can shrink toward zero as they flow backward — so the early layers barely update and the network struggles to learn. This is the vanishing-gradient problem (picture a message whispered down a long line, weak by the end). The deck lists the standard fixes:

  • ReLU activations (instead of saturating sigmoids in deep stacks)
  • Residual / skip connections — give gradients a direct path backward
  • Layer / batch normalization
  • Better weight initialization

The neuron & activation functions

A neuron computes a weighted sum of its inputs plus a bias, then passes the result through a non-linear activation. The non-linearity is essential: without a non-linear activation, stacked layers collapse into a single linear function, no matter how many you stack.

ActivationRange / role
ReLUThe common default for hidden layers.
SigmoidSquashes to 0–1 — good for a single binary probability.
TanhSquashes to −1…1.
SoftmaxTurns scores into a probability distribution over classes (output layer for multi-class).

Layered features

Each neuron checks one simple signal, and depth builds a hierarchy: early layers detect simple features (edges, colors); deeper layers combine them into complex concepts. For example, edges → shapes → "is it a cat?". This automatic feature hierarchy is what makes deep learning so powerful.

Layer normalization

Layer normalization standardizes the activations within a layer to zero mean and unit variance — like normalizing exam scores so different scales become comparable. It stabilizes and speeds up the training of deep networks and is a standard component inside every Transformer block.

Diffusion models

Diffusion models are how modern text-to-image generation works. Training learns to add noise step by step (forward diffusion); generation runs the reverse process to denoise random noise into a new image. It is often guided by a text prompt — the basis of Stable Diffusion-style generators.

Agentic & multimodal AI

  • Multimodal models handle more than text — images, audio, and video together.
  • Agentic AI turns a natural-language goal into actions using tools and APIs (e.g. "set up a meeting with Alex on Friday" → checks calendar, sends invite). The agent loop is plan → act (call a tool) → observe → repeat until done.
  • RAD (Rapid Application Development) — a fast, iterative approach: prototype, get feedback, refine quickly. It favors working prototypes over long up-front specification and suits GenAI apps whose requirements evolve.

Python libraries for LLMs

A library is a reusable toolbox that saves writing code from scratch. The key ones:

LibraryRole
Hugging Face TransformersLoad, run, and fine-tune pretrained models — the most-used.
PyTorch / TensorFlowThe core deep-learning frameworks.
LangChainOrchestrate LLM applications — chains, agents, retrievers.
pandas / NumPyData manipulation; RAPIDS cuDF for GPU-accelerated data.
sentence-transformersProduce text embeddings for search and RAG.
